# Бинго — мультиплеер

Веб-версия классического бинго (75 шаров, карточка 5×5) для игры компанией в реальном времени.
Без зависимостей: сервер на стандартной библиотеке Python, фронтенд на чистом HTML/CSS/JS.

## Запуск

```bash
python server.py
```

или, если Python ставили через uv:

```bash
uv run server.py
```

Откройте http://localhost:8000. Порт можно сменить переменной `PORT`.

## Как позвать коллег

- **Одна сеть (офис, VPN).** В консоли сервера будет адрес вида `http://192.168.x.x:8000` — отправьте его коллегам.
  При первом запуске Windows спросит про брандмауэр: разрешите доступ Python в частных сетях.
- **Все удалённо.** Пробросьте порт наружу, например:
  - VS Code → панель **Ports** → Forward Port `8000` → Port Visibility: **Public**;
  - или `cloudflared tunnel --url http://localhost:8000` (выдаст ссылку `https://….trycloudflare.com`).
- **Постоянный хостинг** — см. раздел «Деплой» ниже.

В игре кнопка **🔗 Пригласить** копирует ссылку прямо в комнату.

## Как играть

1. Один человек создаёт комнату и становится **ведущим** 👑, остальные входят по 4-буквенному коду или ссылке.
2. Ведущий выбирает цель раунда — **линия**, **две линии**, **четыре угла** или **вся карточка** — и начинает раунд.
3. Шары тянутся кнопкой (или **пробелом**) либо автоматически каждые 4–20 секунд.
4. Игроки отмечают выпавшие числа на своей карточке (или включают **автоотметку**) и жмут **БИНГО!**
   Сервер проверяет карточку: ложное бинго видят все 🙈, настоящее — завершает раунд и даёт победу.
5. **Новый раунд** — у всех новые карточки, счёт побед сохраняется.

Ещё: озвучка шаров (🔊), передача роли ведущего и удаление игроков (наведите на игрока в списке),
автоматическая передача роли, если ведущий пропал больше чем на 20 секунд, переподключение после
перезагрузки страницы.

## Деплой (Oracle Cloud Always Free)

Сервер: Ubuntu 24.04 на бесплатном VM.Standard.E2.1.Micro, перед игрой стоит Caddy с автоматическим
HTTPS на домене `<ip-через-дефисы>.sslip.io`. Игра работает как systemd-сервис `bingo` от отдельного
пользователя `bingo`, который может только обновлять файлы в `/opt/bingo` и перезапускать сервис.

Создание сервера с нуля:

```bash
uv tool install --python 3.12 oci-cli
oci session authenticate --region eu-frankfurt-1 --profile-name bingo   # вход через браузер
bash deploy/oci-create-vm.sh                                            # сеть + сервер, печатает IP
scp -r deploy ubuntu@<IP>:/tmp/bingo-deploy
ssh ubuntu@<IP> "sudo bash /tmp/bingo-deploy/setup-server.sh '<публичный SSH-ключ для деплоя>'"
```

**CI** (`.github/workflows/deploy.yml`): на каждый push и pull request гоняется `tests/smoke_test.py`,
а push в `main` после тестов выкладывает `server.py` и `public/` на сервер и перезапускает сервис.
Нужны секреты репозитория `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` и переменная `APP_URL`.

Выложить вручную:

```bash
tar czf - server.py public | ssh bingo@<IP> 'tar xzf - -C /opt/bingo && sudo systemctl restart bingo'
```

Перезапуск сбрасывает идущие игры (комнаты хранятся в памяти) — не деплойте посреди партии.
Oracle может остановить бесплатный сервер при долгом простое: тогда Console → Instances → **Start**.

## Устройство

- `server.py` — HTTP-сервер: API (`/api/create`, `/api/join`, `/api/action`) и живые обновления через
  Server-Sent Events (`/api/events`). Вся логика и проверка бинго — на сервере.
- `public/` — клиент: `index.html`, `style.css`, `app.js`.

Комнаты хранятся в памяти: после перезапуска сервера их нужно создать заново.
Пустая комната удаляется через 3 часа.
